# GoodBit 2.0: how it gets built

The *what* lives in `goodbit-2.0-brainstorm.md`. This is the *how*: the order, the
gates, the measurements each decision waits on, and the rules an agent working
in a worktree has to follow.

Read this before touching anything on a `w1-`, `w2-` or later branch.

## Where it stands

Branch `2.0`, twelve commits, nothing pushed.

**Done:** the whole of wave 0 (the unit suite, the extension list, the export
temp directory, the bench library roots, the scan race, reka-ui) and the whole
of wave 1 except the database driver (migrations, and a backup that can be put
back). Plus two things the user asked for along the way: the OBS setup puts OBS
in the tray, and the GitHub community profile is filled in.

**Found by measuring, not by reading:**

- GoodBits hold in **4%** of clips, so 2.1 is not the headline.
- A warm scan of 284 clips is **89 ms**, so incremental indexing is not worth
  building.
- An export runs at **1.37 s per second of output**, so the export rework is not
  urgent.
- Timing the scan turned up a race that lost clips silently. Three other live
  defects came out of writing tests for things that were not being tested: an
  mkv the scan could not see, two exports sharing one scratch directory, and two
  backups in the same second colliding.

**Wave 2 is in**, all four branches merged: GoodBits' backend, the notes read
mode, the `BaseComboBox`, and the publisher losing ffmpeg. 162 unit tests, and
every touched e2e spec green.

The agents found four things I would not have looked for, three of which only
the built app or a fresh eye could show:

- **The publisher had an unauthenticated file read.** `GET /:filename` joined a
  route parameter onto the upload directory. Express matches the route against
  the still-encoded path, so `%2F` is not a separator when the router decides,
  and the parameter is decoded afterwards.
- **`MarkdownPreview.vue`'s entire scoped style block had never applied**, so no
  heading, code block or timestamp chip has ever rendered in this app.
- **A 404 answered 500**, because `EntityNotFoundError` was matched by `name`
  and rollup renames the class while bundling main.
- **`.gitignore` did not ignore `.env.development`**, the exact filename that
  burned this project's Cloudflare token.

Three of the four needed `npm run build` or a Playwright spec to show up.
`npm run check` was green for all of them, which is the argument for the
integrator building and running rather than trusting a green gate.

**Waiting on the user:** the licence, and the three minute hotkey measurement
that sizes 2.2. Both are in Open questions.

## Why this file exists

The bottleneck on this app has never been writing code. It was the loop: edit,
`npm run build` (typecheck both configs, bundle three targets), relaunch
Electron, click, screenshot, judge. Four to six minutes for a one line change,
and the only automated gate below that was an e2e suite that builds first and
takes minutes more. So logic that decides what the app *does* was checked by
launching the app and looking at it.

Wave 0 exists to fix the loop rather than to add features. Everything after it
is the brainstorm, in an order that lets separate pieces run at once without
merging into each other.

## Safety, which is not negotiable

- **The database is backed up before anything.** `node scripts/backup-db.mjs`
  takes a verified snapshot into `%APPDATA%/GoodBit/backups/`. The pre-2.0 one
  is also copied to `C:\Users\darre\goodbit-2.0-safety\goodbit-pre-2.0.db`,
  outside the app's own directory, so an app that misbehaves cannot reach it.
  At the time it was taken: 278 clips, 53 games, 5 tags, 4 collections, 34 tag
  patterns.
- **`D:\Clips` is read-only.** Copying clips out to test against is fine and
  expected. Nothing writes, renames, trims or deletes in there. A fixture is
  made by copying out and then working on the copy.
- **Every run that could touch data uses `GOODBIT_USER_DATA`**, which redirects
  the whole data directory *and* the single instance lock, so a test run cannot
  see the real library or fight the installed app for it.
- **Nothing is pushed and nothing is released** without the user saying so.
  `2.0` is a local branch.

## The gate, and what each level costs

| Command | Cost | When |
|---|---|---|
| `npm run typecheck:node` | ~15 s | after any change under `src/main`, `src/preload`, `src/shared` |
| `npm run typecheck:web` | ~25 s | after any change under `src/renderer` |
| `npm run test:unit` | under a second | after every change, always |
| `npm run check` | ~40 s | before handing work back |
| `npm run build` | minutes | only when something has to be *run* |
| `npm run test:e2e` | many minutes | see below |

**e2e is not part of the loop.** It builds all three bundles and then drives the
real app. An agent never runs it. Targeted specs get run by the integrator
against an existing build when a wave touched that surface
(`npx playwright test tests/e2e/trim.spec.ts`). The full gate runs **once**,
before a release, after the user has approved the features in it.

**Check the exit status, never the log text.** vite colours its own failures, so
`[31merror during build:` does not match a grep for `^error`. A build that
failed has read as a build that passed here before, and the app went on running
the previous bundle while the fix appeared not to work.

## The brief, for an agent working in a worktree

You have your own checkout, on your own branch, under
`.claude/worktrees/agent-<id>` inside the repository.

**You do not need to install anything.** The worktree is nested inside the main
checkout, so Node's module resolution walks up and finds its `node_modules`.
Verified: `typecheck:node` and `vitest` both run in a fresh worktree with no
`node_modules` of its own. A junction was set up for this and turned out to be
unnecessary.

**Never:**

- `npm install`, or anything that writes to `node_modules`. It is shared, and
  changing it changes it for every other agent at the same moment. If you need
  a dependency, stop and say so.
- `npm run build`, `npm run dev`, or `npm run test:e2e`. Building writes into
  vite caches and costs minutes you do not have to spend. Typecheck is your
  gate.
- Touch `D:\Clips`, `%APPDATA%/GoodBit`, the `main` branch, or another agent's
  branch.
- Change a file outside the surface you were given. If your change needs one,
  say so in your report instead of making it: the file is probably somebody
  else's this wave.

**Always:**

- `npm run typecheck:node` or `typecheck:web`, whichever covers what you
  touched, plus `npm run test:unit`. Both green before you report.
- Write the test with the change, in `tests/unit`, if the logic takes values and
  returns values. If it needs ffmpeg, a database, a window or another program's
  config, it does not belong there; say what you could not cover.
- Read the surrounding code and match it. This codebase explains *why* in
  comments, at length, where a decision cost somebody a debugging session. A
  patch with no comments in a file that is half comments does not match.
- One commit, and a report that ends with **what you could not verify**. That
  list is the integrator's queue. An agent cannot look at a screen; saying "it
  compiles" about a visual change is not a result.

**The house rules that get caught in review** (all of them are in CLAUDE.md,
these are the ones that actually get broken):

- **No em dash.** Anywhere: code, comments, commit messages, UI strings, docs.
  A comma, a colon, a semicolon or a full stop. An en dash in a numeric range
  like `0:20 – 0:26` is correct and stays.
- **No literal colour in a component.** The token ladder in `styles.css`
  (`--muted-50..900`, `--card`, `--border`, `--line-strong`) and nothing else.
  White stays literal only on a brand or fixed-dark ground, like a chip over
  video. Adding `dark:` variants beside literals was tried and shipped visibly
  broken: a variant cannot reach a colour inside a bound `:class`.
- **Business logic is an Action**, in `src/main/actions/`, extending
  `BaseAction`. Not inline in a route.
- **Main's relative imports carry `.js`.** It is ESM at runtime.
- **One switch component.** `Base/BaseToggle.vue`. Never a native checkbox.
- **Long work is a job** (`services/jobs.ts`) with progress, an ETA and an
  `AbortController`, never awaited inside a handler.
- **Destructive actions confirm**, through `toastStore.confirm`.

## Branch names

The integration branch is `2.0`. Agent branches are `w<wave>-<item>`:
`w2-goodbits`, `w2-notes`, `w2-combobox`. **Not** `2.0/<item>`: git refs are
directories, so a branch called `2.0` makes `2.0/anything` impossible, which is
a confusing five minutes if you find it the hard way.

### Wave 1: the schema, once, serially

**1.1 migrations, carrying the whole 2.0 schema in one pass**: `GoodBit`,
`lastOpenedAt`, the FTS tables, everything anybody needs later. This is the
load-bearing decision for parallelism. Three agents each adding a migration
conflict on ordering and produce a chain that only merges by hand.

**Done.** Four migrations, and `scripts/migration-check.mjs` proves them against
a copy of the real 278 clip library: every row kept, the search index
backfilled, a second boot applying nothing, and a fresh database landing on the
same schema as an upgraded one.

**1.2 restore from a backup: done.** It is the other half of 1.1, and the whole
point of a migration release is being able to go back. `restoreBackup` verifies
the copy, copies and verifies the current library first, refuses any path
outside the backups folder, and the app restarts into it.
`scripts/restore-check.mjs` covers seventeen cases, and found a live defect
while doing it: two copies inside one second collided, because `stamp()` is
second-resolution and `VACUUM INTO` will not overwrite.

**1.4 `better-sqlite3` moves to wave 6.** It is a dependency change, and every
dependency moves at the end in one pass. Doing it here means doing the database
driver twice, and the brainstorm pairs it with the Electron bump anyway.

### Wave 2: the fan-out

Five items that provably do not share a file.

| Agent | Item | Surface |
|---|---|---|
| A | **2.1** GoodBits, backend | `src/main` only. Done |
| B | **2.6** notes read mode and timestamp chips | `ClipNotesSection.vue`, `MarkdownPreview.vue`, `timestampParser.ts` |
| C | **3.10** the `ComboBox`, plus `SettingSelect`'s nine call sites | a new `Base/` component, and Settings only |
| D | **5.6** the publisher | `publisher/`, a separate package |
| E | **3.5** breaking up `ObsSetupDialog.vue` | one renderer file |

D shares nothing with the app at all.

**C must not touch `ClipFilters.vue`**, even though the sort control in there is
the obvious second call site. That file is rewritten wholesale in wave 3 by the
header agent, and two agents in it is the one merge conflict this plan can
actually foresee. C builds the component and proves it against Settings; the
header agent adopts it.

### Wave 3: the screens

**3.8 and 3.9 are one agent, not two.** Both rewrite the library's filter row:
3.8 moves *Select* into it and empties the floating bar, 3.9 puts the tag filter
into it, lifts collections above the clips and moves Rescan to Settings. Two
agents in `ClipFilters.vue` and `ClipsPage.vue` at once is a guaranteed
conflict, and the row only wants designing once. Needs C's `ComboBox`.

**3.11 Settings**, in two commits and in this order: the **search field first
and on its own**, then the reorganisation. If it turns out people just use the
search, the taxonomy can stay roughly as it is and the second commit never
happens. Needs C's `ComboBox`, and wants 1.2's restore button to have a home.

Also here: **2.1 renderer** on top of A. **2.3** FTS search, which lands in the
filter row and therefore waits for the header agent. **2.2** the replay key,
after E is out of the dialog and only once its measurement exists. **3.3** frame
stepping.

### Wave 4

**3.1** the export rework, now known to be unhurried at 1.37 s per second of
output, then **2.4** the cross dissolve on top of it, which needs overlapping
frames the current concat pipeline cannot give it. **3.2** one draft store.

**4.2 is dropped as a performance item.** A warm scan of 284 clips is 89 ms. Its
real defect was the race, which is fixed.

### Wave 5, last on purpose

**3.6** the action stack, **3.7** the DTOs, **4.3** the dead code, **4.4** the
small fixes. All four rename or delete across the whole tree. Run them early and
every open branch conflicts.

### The handover, before anything is tested

**A test scenario file goes in `C:\Users\darre\Downloads\` as markdown.** Points
rather than click-by-click walkthroughs: the things worth checking, in the order
somebody would meet them, weighted towards what this release changed and what
no automated test can see.

It is a deliverable rather than a courtesy. Most of what 2.0 changed is visual,
every agent that built a screen reported that it could not look at one, and the
e2e suite asserts geometry and presence rather than whether something reads
well. That gap is exactly what a person testing needs pointing at.

### Wave 6: every dependency to its latest version, right at the end

**Explicitly last, and explicitly not before then.** Patch, minor and major, no
matter the jump, so the Dependabot alerts go quiet and nothing is left behind.
This is the wave that runs after everything else is built and just before the
tree is handed over for testing.

It goes last because a major bump is indistinguishable from a feature bug until
you know the feature worked first. Doing it up front means every failure for the
rest of the release has two possible causes.

What is already known about the hard ones:

- **1.4 is part of this wave, not wave 1.** `sqlite3` to `better-sqlite3` plus
  Electron forward is what the brainstorm lists as one critical and four high
  advisories, breaking on both counts. It was scheduled for wave 1 and moved
  here, because doing the database driver now and again in a full dependency
  pass means doing it twice. Note that `backup.ts` and four `scripts/*.mjs`
  files use `sqlite3` directly, not only through TypeORM, and
  `electron.vite.config.ts` lists it as a native module that must not be
  bundled.
- **`radix-vue` to `reka-ui` is done** in wave 0.
- `electron`, `electron-builder` and `electron-vite` move together, and
  `electron-builder.yml` plus the unsigned NSIS and portable targets have to be
  rebuilt and smoke tested after, not just typechecked.
- `marked`, `axios`, `chokidar`, `fast-glob`, `typeorm`, `vue` and the Tailwind
  line are each capable of a silent behaviour change rather than a type error.
- ffmpeg and ffprobe are pinned static builds. Moving them invalidates measured
  behaviour: the NVENC bitrate floor, the tone map cost, the trim pre-roll fix.
  Anything that moves them reruns `scripts/trim-check.mjs` and
  `scripts/hud-check.mjs`.

How it runs, since "update everything" is not a single command that can be
trusted: one commit per package or per tightly coupled group, `npm run check`
after each, the full e2e gate once at the end, and a real
`npm run build:win` plus `scripts/smoke-packaged.mjs`, because a dependency that
breaks only in a packaged asar is exactly the kind this project has hit before.
`npm audit` before and after, with the numbers recorded.

**Outcome.** Root `npm audit` went 25 vulnerabilities to **0**, publisher 4 to 0. Everything is on
its latest version except two, each blocked by a peer and each recorded in CLAUDE.md: `typescript`
(7.0 ships no API, which `vue-tsc` needs) and `vite` (`electron-vite@5` peers `^7`). `sqlite3` is
gone entirely, replaced by `better-sqlite3`, which also removed the last vulnerable `tar`.

Two things this wave found that no upgrade caused. `goodbit://` had been unreachable from `fetch`
since the Electron 44 bump, because Chromium needs `corsEnabled` on a custom scheme and element
loads are exempt, so every player and thumbnail kept working and only the editor's audio waveform
silently drew nothing. And eighteen off-scale opacity classes, `bg-orange-500/16` and friends, had
never rendered at all under Tailwind 3, including a warning tint added in wave 3.

### Wave 7: the cleanup pass, after the gate and before handover

The user's brief, added mid wave 6. It runs **after the full e2e gate is green**
and **before the tree is handed over**, and it is a refactor: every behaviour and
every pixel stays as it is, down to spacing, colours, focus rings and animation
timing. If a visual test fails, a visual change happened, and that is the whole
contract.

**The live repository is the source of truth**, not the brief's list of paths.
The brief is a snapshot and parts of it are already stale, so every path, script
name and command in it gets checked against `git ls-files` and `package.json`
before it is acted on, and any discrepancy goes in the handover report.

In scope: the git-tracked application code, `src/main`, `src/preload`,
`src/renderer`, `src/shared`. Out of scope and explicitly not dead:
`scripts/*.mjs`, the docs, the site, test fixtures, `build/` and
`electron-builder.yml`. Untracked top-level folders are ignored entirely rather
than tidied.

What it is actually for:

- Collapse repeated component logic into composables, repeated fetch and IPC
  wrappers into services, hand-rolled controls into the `Base/*` components.
- Replace hardcoded style literals with the token ladder, except on the brand
  and fixed-dark surfaces where white is deliberately literal.
- Delete dead code, but only where unreachability can be *shown*. Grep is not
  enough here: components are reached through the router and through dynamic
  `<component :is>`, routes and IPC handlers are reached by registration,
  entities by decorator, bridge methods by string. Anything that cannot be
  proven unreachable is listed as a suspect rather than deleted.
- No new `any`, no `@ts-ignore`, no `@ts-expect-error`. A refactor that breaks a
  type fixes the type.
- No Tailwind class name built by string concatenation; states map to whole
  class names.

**What must not be tidied**, because it looks like duplication and is not, and
each of these is already explained where it lives:

- The migrations. Append-only history, imported rather than globbed, never
  reformatted or given shared helpers.
- The ffmpeg argument builders. Filter order is a performance contract, and the
  only acceptable proof for a shared helper is byte-identical argv at every call
  site.
- `decodeArgs` taking the file as well as the encoder, which exists for cuts
  made before the pre-roll fix.
- The two-pass lossless trim.
- The FTS5 triggers and the search quoting.
- The `it.fails` specs, which record live defects on purpose.
- The toast window's `BLEED` and `MARGIN`, the always-on-top level, the OS drag
  flags, and the action guards.

One concern per commit, `npm run check` after each with the exit status read
rather than the log, single specs while iterating, and the full suite at the
end with zero skips.

**Wave 7 outcome.** The pass found less duplication than the brief expected,
because most of what looks repeated here is deliberate and documented: three
`round` helpers with three different precisions, ffmpeg argument builders whose
filter order is a measured contract, and 83 Action `Input`/`Output` types that
are each Action's declared shape rather than dead exports.

What it did find: 451 lines across eleven files nothing could reach, a twelve
type OBS contract written out in both processes and already drifted in three
places, four copies of `promisify(execFile)`, a superseded second
implementation of the game-folder naming rule, and `src/shared` still carrying
the `package.json`, lockfile and tsconfig of an architecture two rewrites ago.

Two things were deliberately **not** done and are reported instead, because
both would move pixels and the brief fixes appearance: 124 literal colour
utilities cannot become tokens while `--danger` is `hsl(0 84% 60%)` and
Tailwind 4's `red-500` is an `oklch` value, so the swap is not free; and
`text-yellow-900` / `text-yellow-800` / `text-purple-900` are light text that
would be unreadable on a dark ground, which is a defect to fix on purpose
rather than inside a refactor.

## Measurements

The brainstorm gates four decisions on numbers that did not exist. Taken up
front, in one pass, so nothing gets built on a guess. **Three came back low and
resized the release.**

| Question | Decides | Result |
|---|---|---|
| How many clips hold two or more confident HUD events? | whether **2.1 GoodBits** is the headline | **4%**. 7 of 174 real clips. Against the 15% bar the brainstorm set itself, so **not the headline** |
| How long does a whole-library scan take? | whether **4.2** is worth it | **89 ms** warm for 284 clips, 0.31 ms each, against 4,662 ms cold. **Not a performance problem** |
| How long does a real export take? | how big **3.1** is | **1.37 s per second of output** on real 3440x1440 AV1. A half-minute movie is about forty seconds. **Not urgent** |
| Does `RegisterHotKey` fire under an elevated foreground? | whether **2.2** is the second best item on the list | **needs the user**, see Open questions |

Run them again with:

```bash
node scripts/hud-check.mjs "Battlefield 6" --limit 200 --json tmp/hud.json
GOODBIT_REAL_CLIPS=<a folder of real recordings> npx playwright test tests/e2e/measure.spec.ts --reporter=line
```

**What the scan number actually found.** Timing it turned up a bug rather than a
bottleneck: nine things start a scan, none of them knew about each other, and
two at once both insert the same new clip, so one loses on
`UNIQUE constraint failed: clip.filePath`. On the watcher path that was caught
and logged, so the clip silently never appeared; through `POST /scan` it was a
500. Fixed, and the regression test was verified to fail without the fix. **So
4.2's value was never the speed.** What is left of it is whether a scan should
be incremental at all, and at 0.31 ms per clip the answer is no.

**Two more things out of the same run.** An mkv now indexes, keeps its duration,
survives a second sweep and **plays in this Electron's Chromium**, which was the
open question behind indexing it at all: a clip that indexes and cannot play
looks exactly like a broken recording. And the export bench exercised the
temp-directory fix under a real render.

**Where the release's weight went instead.** With GoodBits at 4%, the scan fast
and the export tolerable, what is left that somebody would notice is the
foundation (1.1 to 1.4) and the screens (2.6, 3.8, 3.9, 3.10, 3.11). That is
the shape of 2.0 now, and it is not the shape the brainstorm was written in.

## Open questions, which need the user

- **1.5, the licence.** `package.json` has no `license` field and there is no
  `LICENSE` file. This is a decision about other people's rights to the work,
  not an engineering one, and publishing under the wrong one is not undoable.
  Nothing else waits on it.
- **2.2's measurement.** `scripts/hotkey-check.mjs` needs a person: press F9
  with the console focused, then with Task Manager focused, then with a terminal
  started as administrator focused. Synthesising those keypresses would measure
  the wrong thing, since injecting input into an elevated window is exactly what
  UIPI blocks. Three minutes of hands, and it decides how big 2.2 is.

## Decisions taken here

- **The whole 2.0 schema lands in one migration**, in wave 1, before any feature
  agent forks. Columns nobody uses yet are cheaper than two migration chains.
- **`decide.ts` reaching `electron`** through `model.ts` is stubbed for the unit
  suite rather than refactored. Agent A owns that file in wave 2 and should
  invert it then: pass the model in rather than have the decision go and find
  one.
- **Two live defects in the timestamp path are recorded as `it.fails`** rather
  than fixed, because 2.6 owns that file. Fixing either makes its test fail,
  which is the announcement.
- **2.1 is no longer the headline**, on its own measurement: 4% of clips, against
  the 15% bar the brainstorm set. It still ships, and **marking by hand is now
  the interesting half of it**, since a person knows a clip has two good bits
  whether or not a kill banner appeared, and that path needs no detector at all.
- **They are called GoodBits, not moments.** The user's call, and it is the
  better name: the app is GoodBit and its whole promise is pointing at the good
  bit, so the unit it deals in should say so. Entity `GoodBit`, table
  `good_bit`, `GoodBitDTO`, `CreateGoodBitAction` and so on, and
  `SuggestedMoment` in `ClipSuggestionsDTO` becomes `SuggestedGoodBit` with its
  `moments` field becoming `goodBits`. **Ordinary English uses of the word
  "moment" stay**, and there are plenty: the loudest moment of a clip,
  momentary loudness, "the moment you pressed save". A blanket rename over this
  repository would be wrong, which is why it was done by hand.
  The rename went into the migration **in place** rather than as a second
  migration, because no real database had it applied: verified against the live
  file, which still had its original ten tables and no `migrations` table.
- **4.2 is dropped as a performance item**, on its own measurement: 89 ms for a
  warm scan of 284 clips.
- **3.8 and 3.9 are one agent.** Both rewrite the library's filter row, and two
  agents in one file is the only merge conflict this plan can see coming.
- **3.11 ships its search field before it moves anything.** A reorganisation
  that only renames things replaces one wrong learned answer with another; the
  search is what makes the move safe, and it may turn out to be the whole fix.
- **Every dependency moves in wave 6, at the very end.** A major bump is
  indistinguishable from a feature bug until the feature is known to work, so
  doing it first would give every failure for the rest of the release two
  possible causes.
- **The community health files are being written on `w0-community`**, off in a
  worktree, since they touch nothing under `src/`. That branch carries a
  `LICENCE-DECISION.md` laying out the options rather than a `LICENSE`, because
  the choice is still the owner's.
